Roadmap

Projects and config

drachm.toml, dependencies, [behaviour], [warnings], file flags and tests.

A project is a folder with a drachm.toml. build, run and check take the folder, and the program starts in the entry file. The [project] section is built; the other sections are the design, and each one is marked until it builds.

A new project

drachm new mygame makes drachm.toml, src/main.drh and a tests/ folder.

drachm.toml

name is required. It must be a plain name (letters, digits and _). The source root is the folder of the entry file, so a path that starts with the name begins there. A library has no program to run: drachm run and drachm build say so (E0811), while drachm check checks the library without requiring main().

Dependencies

A dependency is a folder on this machine (path) or a git repository at a tag. Both are built: the compiler finds the folder, reads its own drachm.toml and resolves its dependencies in turn. A registry version such as json = "1.2" is not supported yet (E0901): the Agora comes later.

A git dependency is cloned with git, which must be on the PATH, into deps/NAME@VERSION in the project's folder. Versions are tags: tag = "v0.4" names one, version = "^0.4" takes the newest tag inside a range. The tag, the commit and a SHA-256 hash of the files are written to drachm.lock beside drachm.toml, and the next build uses that commit even if the tag moves later. If the tag moved and the commit is not in deps/, the build stops (E0809); a package whose files differ from the hash is refused (E0816). Commit the lock file; deps/ is git-ignored. drachm add, remove, update and install manage all this: see Packages.

Dependency imports

A dependency obeys its own drachm.toml. It publishes module paths with public_modules = ["survey.readings"] under [project]. Import a listed module through the alias declared under [dependencies], for example in chart_depth from charts.survey.readings;. Each module exports its own items with out. The dependency can import its private modules internally.

Native libraries

The [native] table names what C imports need: include (header folders), defines, libraries (or link), library_dirs and sources (C files compiled with the project). A project that imports a dependency links what the dependency's table asks for. unsafe = true in the same table lets every file of the project use unsafe (C calls and raw pointers) without the file flag; a dependency's own table says the same for its files, so an app needs nothing for it. See C imports.

Build settingsNot implemented yet

opt = true makes build and run act as if -O was given. Only the machine the compiler runs on can be the target.

Behaviour settings

Settings that change what a program does live in [behaviour]. Each has a default.

Bounds

bounds = "panic" checks collection indexes at runtime. With unchecked, the runtime check is omitted. A negative index still counts from the end. The compiler still checks constant array indexes.

Unsigned negation

unsigned_negate = "wrap" keeps the operand's unsigned type. With error, negating a typed unsigned value is a compile error (E0101). With signed, the result has the next wider signed type. Widening uint128 requires sint256, which is not implemented yet (E0901).

Missing map keys

missing_key = "panic" makes map[key] return the value directly and stops the program with exit status 101 if the key is missing. The default, optional, returns an optional. map::get(key) always returns an optional.

Overflow

overflow says what happens when a whole number does not fit its type. It covers + - *, unary -, / (the smallest signed value divided by -1), **, ++ and --, shifts, constants that do not fit, conversions (automatic ones and ::to<T>()), and the scaling of units: x::in<km>() and mixed-unit arithmetic (Units).

Under saturate, a negative shift amount shifts the other way: 8 << -1 is 4 and 8 >> -1 is 16. Shifts never clamp, though: bits pushed past the width fall off in either direction, so 200 >> -1 and 200 << 1 in uint8 are both 144.

A float turned into a whole number drops its fraction first. NaN becomes 0 under wrap and saturate, and the infinities become 0 under wrap but clamp to the type's largest or smallest value under saturate (+inf gives the maximum, -inf the minimum). Under panic NaN and the infinities stop the program.

A constant that does not fit is W0102 and is changed (wrap wraps it, saturate clamps it); under panic it is an error (E0116), since the program could never run it.

The setting applies per function: the project's [behaviour] merged with the //--!$overflow: flag of the file the function is written in. Generic functions and methods use the setting of the file that defines them.

Unhandled failures

unhandled_fail = "error" (the default in a project) makes a call to a failing function without maybe, fails or fails with a compile error (E0544). With crash, the call stands: if it fails, the program prints the failure's message, as a failure that leaves main would, and ends with the failure's exit code (the exit of its variant, or 1). A call that has handlers for only some of the failures it can raise crashes on the others. Nothing in the program is cleaned up on the way out, as with a failure that escapes main.

A lone .drh file with no drachm.toml beside it, and a script, use crash by default.

Import clashes

import_clash = "warn" (the default) makes an in * import that brings a name the file already has a warning (W0240): a declaration of the file wins over any import, and between two imports the first one wins. With error the same clash is an error (E0242), so a project can forbid hiding names this way. A dependency follows its own drachm.toml. A name that hides a module (W0241) and two modules of one name (E0232) are not affected.

WarningsNot implemented yet

[warnings] can make named warnings into errors, and can switch off lints such as the one for a copy that does nothing on a number (W0322).

File flags

A line //--!$key: value at the very top of a file overrides the project setting for that file. Use //--!$unsafe: true to allow unsafe code in that file (or unsafe = true under [native] for the whole project).

overflow, bounds and unsigned_negate take effect per file. missing_key, unhandled_fail and import_clash are project-wide: a file flag that sets one is an error (E0806).

Tests

A test block in any file is a test, and drachm test runs them all. Built: see The test keyword.
