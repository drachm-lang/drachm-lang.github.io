Numbers without surprises

Mixing number types, the left-side rule, lossy conversions, wrapping, exact constants and how decimals print.

Numbers are where programs quietly go wrong. A whole number overflows, a decimal is cut off, or a calculation runs in a type you did not expect. Drachm cannot stop you from writing such code, but it makes each of these moments visible: it either does the obvious thing, or it warns you and shows how to say what you meant. This guide covers those rules in the order you will meet them. Lesson 2 has the basics, and Types is the reference.

The left side leads

When two numbers of different types meet in a + b, a < b or any other two-sided operator, the right side converts to the type of the left side, and the calculation is done in that type. Nothing else is guessed. The rule has no exceptions for decimals, which is the part that surprises people.

With a uint32 called hp, hp * 1.5 is a whole-number calculation. The 1.5 is turned into a uint32 first, so it becomes 1, and the compiler warns you that it dropped the fraction:

You can also stay with whole numbers: hp * 3 / 2 multiplies first, so no fraction is lost until the very end.

A constant on the left takes the type of the variable on the right if it fits there. 300 does not fit a uint8, so it keeps a type of its own and leads the sum.

One more thing to notice: (hp * 1.5)::to<uint8>() still warns. The ::to<uint8>() applies to the result, and the 1.5 was already cut down before that. Rewrite the calculation, then convert.

Lossless and lossy conversions

A number moves between types automatically, but not always silently. The compiler asks one question: can the target type hold every value of the source type? If so, the conversion is lossless and nothing is printed. If not, it is lossy, and you get warning W0102.

Lossless means:

  • a whole number to a whole-number type that covers its whole range: uint8 to uint32, uint8 to sint16, sint32 to sint64;
  • a whole number to a decimal type that holds every such value exactly: up to 16 bits into float32, up to 32 bits into float64;
  • float32 to float64.

Everything else is lossy: a narrower type, a sign change, a decimal to a whole number, or a wide integer into a decimal. This program converts six times, and every one warns. Note how the note: line says what each type can hold, so you can see which values would be lost.

Only four of the six warnings are shown above; the other two (sint32 to uint8, and uint64 to float64) look the same. A warning does not stop the build, but treat it as a question: did you mean to lose this?

Saying "I meant it" with ::to

value::to<T>() converts a value to the number type T and never warns, because you asked. Use it when losing information is the point: cutting a decimal to a whole number, packing a value into a byte, or reading the low bits of a larger number.

The values that do not fit follow the same rule as everywhere else, which is the next section. For decimals going to whole numbers the fraction is dropped first (toward zero), so 3.99 becomes 3. It does not round.

Overflow wraps around

Arithmetic that goes past either end of a type wraps. A uint8 has 256 values, so 250 plus 10 is 260, which is 4. A sint8 after 127 goes to -128, and a uint32 below 0 goes to the top. The same holds for ::to<T>(): whole numbers keep their low bits.

Two details matter. The sum is made in the type of the left side, and only then widened if it goes into a wider variable. big + big with two uint8 values of 200 is 144, even when it is stored in a uint32. To get 400, convert one side first.

A uint8 counter pushed past its end ends up at 4 after ten steps.

A signed number wraps to the other end, and a uint32 going below zero goes to 4294967295.

The left side leads here too. wrapped is 144, while wide converts first.

::to<T>() on a value that does not fit keeps the low bits, and 3.99 loses its fraction.

Dividing a whole number by zero is different: it stops the program with a message on stderr and exit code 101.

If the zero is a constant written in the source, it is caught earlier. See the constants section below.

Choosing another overflow behaviour

A project, or one file, can choose what happens on overflow: overflow = "wrap" (the default), "saturate" (clamp to the nearest end) or "panic" (stop with exit code 101). It covers arithmetic, shifts, conversions and constants that do not fit. In a file, write //--!$overflow: saturate at the top. See Overflow.

Constants that do not fit

A number written in your source is a constant, and it has no type yet. When it lands in a typed place, the compiler checks that it fits. If it does not, you get the same W0102, but with the value it becomes shown under the arrow. That is the line to read: it says exactly what your program will hold.

Most of the time the fix is to pick a bigger type, or a value that fits. Shifting a constant by too much is a close relative, with its own warning: 1u32 << 40 shifts by 8, because the amount wraps around the 32-bit width (W0106).

Exact constants

Arithmetic on constants is done exactly, with no limit on size, and only the final result has to fit where it is stored. So 2 ** 100 does not overflow, 2 ** 100 / 2 ** 95 is exactly 32, and 0.1 + 0.2 is exactly 0.3. The comparison 0.1 + 0.2 == 0.3 is true for constants.

Once the numbers are in float64 variables, they are ordinary binary decimals, and a + b == 0.3 is false. That is how computers store decimals, and it is why you rarely compare decimals with ==.

How decimals print

::text() on a decimal prints the shortest digits that read back as the same number, always with a decimal point and never in exponent form. So 1.0 prints 1.0, a third prints 0.3333333333333333, and 1e21 prints as a one followed by twenty-one zeros and .0.

Constants are exact, so the sum is exactly 0.3.

The same sum in variables carries the usual binary error: 0.30000000000000004.

A float32 has fewer digits than a float64. Widening one to float64 shows what it really stored, 0.10000000149011612.

Dividing whole numbers drops the fraction (42 / 4 is 10), so divide decimals when you want one.

For display, io::outf rounds: %.2 is two decimal places, %8.3 is a width of 8 with three places, and %-8.1 pads on the right.

Decimal division by zero does not stop the program. It follows the usual standard and gives inf or nan.

A checklist

  • Put the type you want the answer in on the left.
  • Read every W0102. It tells you what the value will become.
  • Use ::to<T>() only when losing information is on purpose.
  • Remember that whole numbers wrap and that decimals keep their fraction until you convert them.
  • Print money, measurements and results with io::outf formats, not with long raw decimals.
