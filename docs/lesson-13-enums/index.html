Lesson 13: Enums and optionals

Values that are one of several variants, taking them apart with match, and the optional type T?.

Enums and optionals (T?) both work in the compiler today.

Goal: model a value that is one of several shapes, and handle a value that might not be there.

An enum

An enum is a value that is exactly one of several named variants. A variant can carry data, written in parentheses after its name, and a trailing comma is fine.

Shape is a circle with a radius, a rectangle with two sides, or empty.

When the type is known from the declaration, the variant name alone is enough.

Shape::Empty always works, with the type written out.

Taking a variant apart

match looks at which variant a value is. Each case names a variant and gives its data typed names. Like every match (lesson 7), leaving out a case is a warning.

Circle(float64 r) matches a circle and names its radius r.

A rectangle brings two names.

Empty carries nothing, so it needs no parentheses.

Enums that own data

A variant can hold a string. Then the enum owns memory, so it moves like a string does instead of copying. match looks at it where it is and does not move it, so a case that ignores the data (case Text(_)) leaves the value whole.

To use the data, the pattern has to say what happens to it. take string body moves the text out of the value, and the value is used up afterwards. copy string body makes a copy and leaves the value alone. A plain string body is an error (E0528) that offers both. Numbers and bools bind plainly, as in Circle(float64 r).

A case can also carry a guard (case Circle(float64 r) if r > 10.0), several patterns that bind the same names (case Circle(float64 x), Rect(float64 x, _)), a constant inside the pattern (case Rect(2.0, float64 h)), and patterns inside patterns. The reference page on enums has them all.

A value that might be missing

T? is an optional: either a value of type T or none. It is an enum with two variants, so everything above applies to it. The word none is both the "returns nothing" type and the empty optional.

A variable of optional type with no value starts as none. A T goes to a T? by itself: uint32? age = 42; needs no wrapping.

age has no value, so it is none, and maybe unwraps an optional and gives a fallback when it is none. has value and is empty ask the same question in words. Or match on it, as with any enum: a case with a typed name for the value, and case none for the empty one.

x == none is not how you test for it: the compiler says to write is empty. The optionals part of the reference lists the rest.
