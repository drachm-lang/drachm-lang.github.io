Lesson 15: Generics and interfaces

Functions and structs over any type, interfaces, with, changes self and Self.

Goal: write code that works for many types, and describe what a type must be able to do with an interface.

A generic function

Type parameters go in <> after the name. The compiler works the type out from the arguments, and you write it out only when it cannot.

T stands for any type that can be compared with >.

Both arguments are uint32, so T is uint32 without being said.

The numbers 5 and 9 have no type of their own, so max<uint32>(5, 9) writes it out.

A struct can take a type parameter too. Stack<string> is a stack of strings, and push works for any T.

Your turn: a generic min

Write T min<T>(T a, T b) that returns the smaller of the two, and call it on whole numbers and on decimals.

solution

Interfaces

A generic function that calls methods on its T needs to know they exist. An interface lists the methods a type must have. It has signatures only, no bodies. A struct says which interfaces it implements with with, and several are joined with and.

Shape asks for an area method that returns a float64.

Circle says with Shape, so the compiler checks that it has area.

The method is the ordinary one from lesson 6.

A function that takes &Shape works with any struct that has the interface.

An interface name used as a type means any struct that has it, and the right method is picked while the program runs: none report(&Shape s) { ... }. A type parameter can ask for an interface with with as well: float64 total<T with Shape>(T[?] shapes), which is in the reference.

Methods that change self

A struct method is checked from its body: the compiler knows whether it only reads self or changes it. An interface has no body to look at, so a method that may change self says so after its parameters. A struct's method may not change more than the interface allows. This is written only in interfaces.

bump may change the counter.

get only reads it.

Your own iterables

A type works with for (T x of thing) when it says with Iterable<T> and has a method T? at(uint64 i). The loop calls at(0), at(1), ... until one gives none. The value is only read, so it can be walked again.

A type can be Iterable over several item types. The variable's type picks which at the loop uses.
