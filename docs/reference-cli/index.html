Roadmap

Roadmap

Command line

build, run, check and explain, the -O flag, and exit codes.

The compiler has these commands: new makes a project, add, remove, update and install manage its packages, lsp starts the language server for editors, and the others work on a file or project folder. -O works with build, run and test; --locked works with build, run, check, test and install; nothing else takes a flag.

build and run

build writes an executable. Without -o the file is named like the source, without its .drh extension, so build hello.drh writes hello. run builds the program in a temporary place, runs it and removes it afterwards. The program gets your standard input, so printf '1\n2\n' | drachm run sum.drh feeds it two lines. Compiler warnings are printed first, and the compiler exits with the program's exit code.

A main that returns sint32 sets the exit code, and a none main() exits with 0.

test

test builds each test "name" { } block of the file or folder as a program of its own and runs it, so a test that fails does not stop the others. It prints one line per test, shows the output of the failing ones, and exits with 1 if any test failed. See The test keyword.

check

check reports errors and warnings and writes nothing. Use it while you edit, as the lessons do, because it is the fastest way to see whether a change compiles.

lsp

lsp runs the language server. An editor starts it and talks to it over standard input and output; you do not run it by hand. See Editor support.

new

new makes a project folder in the current folder: drachm.toml, src/main.drh with a greeting, and an empty tests/ folder. The name must be a plain name (letters, digits and _, not starting with a digit), and the folder must not exist yet. Then drachm run NAME runs it.

The folder also gets a .gitignore with deps/ in it (fetched packages are not committed).

add, remove, update, install

These four work on the project in the current folder (the one with the drachm.toml) and are described in Packages.

Each prints what it did, one line per change. A command that fails changes nothing in drachm.toml. NAME may be written with - or _ (sdl-drh finds sdl_drh).

--locked

--locked makes the dependencies come from drachm.lock alone. Nothing is resolved anew, nothing new is fetched and the lock file is not written. If the lock is missing or does not cover drachm.toml (a dependency was added, removed or its tag changed), the command fails with E0818, and drachm install (without --locked) or drachm update brings the lock up to date. A fetched package whose files do not match the lock fails with E0816. See Packages.

explain

explain prints the title and description of one code. An unknown code is an error.

-O

-O gives an optimised build. The compiler writes C and calls your C compiler (cc, or clang on Windows), so the build is slower and the program much faster. Both builds print the same output, and the compiler's tests check that. It does not change what the program means. Set NO_COLOR to turn off coloured diagnostics.

Project folders

Instead of a file, build, run and check take a project folder: one with a drachm.toml. With no argument they use the current folder. The program starts in the file entry names under [project] (src/main.drh by default), and the folder of that file is the source root. A file inside a project belongs to it; a file with no drachm.toml above it is a script and its own folder is its root. The nearest srachm.toml also selects script mode. Scripts can start with top-level statements and use local imports. See Scripts.

A project with kind = "library" has no program: build and run say so (E0811), and check checks it without requiring main(). A folder with no drachm.toml is an error (E0814), and so is a missing entry file (E0812). The settings are described in Projects and config.
