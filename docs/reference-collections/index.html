Arrays and lists

Array and list types, literals, indexing with bounds checks, changing a list, its methods, comparing, for loops, splitting strings into lists, and maps with their keys, updates and walks. Parts still to come are marked.

An array holds a fixed number of values side by side; a list holds any number and grows. Both hold values of one type. The rules on this page are what the compiler accepts today; the parts still to come are marked.

Arrays and lists

T[N] is an array of N values (N is a whole number of 1 or more), and T[?] is a list. They can be stacked (uint32[?][?] is a list of lists) and used anywhere a type goes: locals, parameters, results, struct fields, enum payloads and optionals (uint32[?]?). A literal is the values in brackets, with a trailing comma allowed; its type comes from the place it is used. With no type to take from, the first value decides and the result is a list.

A list declared without a value starts empty and can be used at once (mut string[?] names;). [] needs a type to say what it holds (string[?] xs = [];), or it is E0624. An array literal must give exactly as many values as the array has (E0625), and the values of one literal must be of one type (E0623 when the list has no type of its own to convert to).

A list owns its memory, so it moves like a string: passing it, returning it or assigning it hands it over, and it is freed when its owner ends. copy xs makes an independent copy, items included. An array owns what its items own. It copies by itself, like a small struct, when its items copy and it is at most 32 bytes, and moves otherwise.

A list of borrows is spelled List<&string> (&string[?] is a borrow of a list). It is tied to what its items borrow, like any holder; contains and == compare what the items point at (E0901 for items that are &Shape). none is not an item type (E0104), an array cannot contain itself (E0210; a list can, since it holds its items on the heap), and an array above 1 MiB is E0901.

Indexing

xs[i] is the item at position i, counting from 0. The index is any integer type of at most 64 bits, without a unit. A negative index counts from the end, like text: xs[-1] is the last item. An index outside the list stops the program with exit code 101 and says which index and what length. A constant index into an array is checked while compiling (E0620).

An item is a place: xs[i] = v;, xs[i] += 1;, xs[i]++ and xs[i].field = v; write to it, and &xs[i] borrows it. Reading an item whose type owns memory (a string, a struct holding one) would leave a hole, so it is E0622: look at it with &xs[i], copy it with copy xs[i], or call a method on it. To take one out, see Taking an item out.

An index is evaluated once, so xs[f()] += 1 calls f once. Two borrows of items of one list count as borrows of the same place: &mut xs[0] and &xs[1] conflict.

Changing a list

A list changes through xs::push(item), which moves the item in, and through its items; both need a binding that allows changes (mut, open, or a &mut borrow), or the compiler says so (E0205, E0311). xs::len() is the number of items (a uint64) and works on arrays too. A method that pushes onto a list in self makes the method one that changes self.

A borrow of an item keeps the list from changing: push while &xs[0] is still used is E0302.

Reading and removing items

xs::pop() takes the last item out, and xs::remove(i) takes the item at i out (the items after it move down). Both give the item, pop as a T? that is none for an empty list; remove stops the program when i is outside the list. xs::insert(i, item) puts an item in at i (i may be the length, to add at the end). xs::clear() drops every item and keeps the list usable.

xs::get(i), xs::first() and xs::last() give the item as a T?, which is none when there is no such item, so they never stop the program. They copy the item, so for items that copy (numbers, bool, Copy structs) that is all there is to it. For items that own memory (string, structs with a string) the answer is a view of the item: an optional that holds a borrow of the list (written maybe &string). While the view is in use the list cannot change (push is E0302), exactly as for &xs[0]. copy xs::first() gives an owned T? copy of the item instead, and a view cannot be assigned to an owned string? (E0531, which points at copy). Read a view with maybe &fallback, has value, or match with a &T pattern: case &string n { ... }. xs::join(sep) puts the items of a string[?] together with sep between them ("" for an empty list).

xs::contains(item) is true when some item is equal to item. Lists and arrays compare with == and !=: they are equal when they have the same length and each item is equal to the item at its place. Items compare with their own == (numbers, bool, string, structs and lists of those; an enum with values is E0527). On items that own memory, contains takes the value written with &, names::contains(&name), so the search does not move it; without the & it is E0101.

xs::containsRef(&p) is the address version of contains: true when some item is a borrow of exactly the place p, even if another place holds equal text. It works on lists of borrows (and optionals of them), and on owned items it is E0633, which says to use contains.

Walking a list

for (T x of xs) goes over the items in order, with &T x for a view and &mut T x for a changeable view; the loops page has the rules and the example.

xs::each(f) calls a function value for every item of a list or array in order. See Collection callbacks for parameter types and an example.

Taking an item out

take xs[i] reorders moves the item at i out and gives it. The last item fills its place and the list gets one shorter, so the order of the other items is not kept. It is the way to take an owning item (a string, a struct holding one) out of a list. take xs[i] leaving v keeps the length and the order: the item moves out and v takes its place. A plain take xs[i] is E0901 for now.

Splitting strings

text::split(sep) gives the pieces between the occurrences of sep, in order, as a string[?]. Empty pieces are kept, so ",a,,b," gives five pieces and "" gives one empty piece. text::lines() gives the lines without their line ends (\n or \r\n); a last line without a line end counts, and an empty text has no lines. text::chars() gives the characters, one owned string each, counted the way len() counts them. Every piece is a copy, so the list keeps working after the text is gone. An empty separator gives the same grapheme clusters as chars().

join goes back: parts::join(sep) puts the items of a string[?] together.

Maps

Map<K, V> holds values under keys, and OrderedMap<K, V> does the same and keeps the entries in the order they were added. A literal lists the entries in braces, { key: value, ... }, and its type says what the keys and values are. A map declared without a value starts empty and can be used at once.

By default, m[k] gives the value as an optional: none when the key is missing, so m[k] maybe 0 is the value or a fallback. With missing_key = "panic", m[k] returns the value directly and stops on a miss. m::get(k) always returns an optional. m[k] = v; adds the entry or replaces its value, m::set(k, v) does the same as a method, m::remove(k) takes the entry out, and m::len() counts the entries. Changes require a mut or open binding, or an &mut borrow.

Keys can be whole numbers up to 128 bits, bool, string, floats, and structs, enums, optionals and arrays made of those (see below). A float key is compared by its bits, so NaN finds itself and -0.0 and 0.0 are different keys. A map owns its keys and values, which move in when they are added. Reading a value with m[k] or m::get(k) returns an independent copy. This allocates for owned text and can allocate for nested collections.

A type that cannot be hashed cannot be a key: lists, maps, borrows and pointers give E0626.

An empty {} needs a type to take, as an empty list does (E0624).

Updating an entry with an operator

m[k] += v; (and -=, *= and the other compound operators) reads the value under k, combines it with v and puts the result back. The map and the key are evaluated once. A key that is not in the map stops the program (exit code 101): there is no value to change, so add the first entry with m[k] = v;.

Walking a map

for (string k, uint32 v of ages) visits each entry, with a copy of its key and value in the two variables. The each method does the same with a callback, ages::each((string k, uint32 v) => { ... }), or a named function that takes the key and the value. Entries come in the order the map keeps them, which is the order the keys were first added. Replacing a value keeps the entry where it is; removing an entry and adding the key again puts it last. The loop borrows the map, so its body cannot change it.

Looking at the entries without copying them (&string k) is not supported yet and gives E0901. A single loop variable over a map is an error: a map is walked with two.

Composite keys and key()

A struct, enum, optional or array is a key when everything inside it can be a key. A map hashes and compares these field by field, a variant's tag first and then its values, so none and an empty string? are different keys.

A struct with a key() method is hashed and compared by what key() returns, and its own == stays what it is for ordinary comparisons. key() takes nothing, is not static, and returns something that can be a key (E0628 otherwise). A struct with its own == and no key() cannot be a key, because a map could not know how to hash it (E0627), and neither can a struct that holds one. Borrowed values

A map may store borrowed values (Map<string, &string>) or structs that hold a borrow. The map becomes a borrower of what its values borrow, so those must outlive every later use of the map (E0306 otherwise). Keys cannot be borrows (E0626).

Generic functions over lists

A generic function can take a list: &T[?] takes any list by borrow, and T is worked out from it, as for any other parameter. See Generics.
