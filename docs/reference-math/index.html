Maths

The math module, the number constants, and how units go through the functions.

The math module holds the number functions. Import it with in math; and call a function as math::name(...):

Every function works in the number type of its arguments: float64 stays float64 and float32 stays float32. The C library computes the results, on both backends, so NaN, infinity and negative zero come out the same either way.

The functions

FunctionTakesGives
sqrt(x)a float or a whole numberthe square root; the powers of the unit halve; fails for a negative x
pow(x, y)floats, or whole numbersx to the power y; with a unit, y is a constant whole number; fails for a negative x with a fractional y
exp(x)a plain floate to the x
log(x), log2(x), log10(x)a plain float or whole numberthe logarithms; fail for zero or less
hypot(x, y)floats of one unitthe square root of x * x + y * y; the unit stays
floor(x), ceil(x), round(x)a float or a whole numberthe whole number below, above or nearest (half away from zero); the unit stays
sin(a), cos(a), tan(a)a plain float (radians) or an anglethe ratio, a plain float
atan2(y, x)floats of one unitthe angle in radians: a float64<rad> in a file with in si;, a plain float otherwise
abs(x)any numberthe size without the sign; the unit stays
min(a, b), max(a, b)numbers of one unitthe smaller or the larger
clamp(x, low, high)numbers of one unitx, held between low and high

abs, min, max and clamp also work on whole numbers of every width. sqrt, log, log2, log10 and pow have a whole-number version, described in Whole numbers below. exp, hypot, sin, cos, tan and atan2 have none: a whole number is an error with the fix in the message, because the conversion should be your decision:

A constant is fine: math::sqrt(2) takes 2 as a float, like every place that wants a float.

NaN, zero and the ends

  • min and max give NaN when either argument is NaN. clamp gives NaN when x is NaN. The bounds of clamp are a range in either order: math::clamp(5.0, 10.0, 0.0) is 5.0.
  • abs(-0.0) is 0.0. round, floor and ceil keep the sign of a zero.
  • sqrt of a negative number, and a logarithm of zero or less, are not NaN or minus infinity: they fail with math::MathError, see Failures below. A NaN given to them comes back as NaN, and sqrt(-0.0) is -0.0.
  • The abs of the smallest signed whole number (-128 as a sint8) does not fit. It follows the function's overflow setting, as -x does: it wraps by default, stops at the end with saturate, and panics with panic.

Failures

sqrt of a negative number, log, log2 and log10 of zero or less, and pow of a negative base to a fractional exponent have no answer. Each one fails with math::MathError, so the call is used like any other call that can fail: give a fallback with maybe, handle the cause with fails with, or pass it up with fails:

MathError says which rule was broken:

CauseWhen
NegativeSqrtsqrt of a number below zero
NonPositiveLoglog, log2 or log10 of zero or a number below zero
NegativePowerpow of a number below zero to an exponent that is not a whole number

The whole-number versions fail the same way. Name the failure as math::MathError, or import it with in MathError from math;. The method spelling needs no import for the call (x::sqrt() maybe 0.0), only for naming the failure. A project that sets unhandled_fail = "crash" (and every script) ends the program with the message when a call is left without a handler; elsewhere an unhandled call is E0544. See Errors.

Two spellings

A module function and a method are the same function:

math::sqrt(x) and x::sqrt() are one function. The method spelling works on any number in any file, with no import. Only the module spelling needs in math;. After the first call, a chain continues with ->.

Constants

The constants belong to the number type, at the precision of that type, and need no import:

float64::pi, float32::pi, float64::e, float32::e, float64::tau and float32::tau (tau is two times pi).

Units

Units go through the functions. sqrt halves the powers:

  • sqrt(9.0<m^2>) is 3.0<m>, and sqrt(4.0<km^2>) is 2.0<km>. A unit with an odd power has no square root (E0410): sqrt(8.0<m^3>) is an error.
  • abs, min, max, clamp, floor, ceil and round keep the unit. The arguments of min, max, clamp, hypot and atan2 must be the same kind of unit (E0401); they are brought to the first one's unit, so math::min(2.0<m>, 150.0<cm>) is 1.5<m>. A plain number beside a measure is E0408, except zero.
  • sin, cos and tan take a plain number, which is radians, or an angle. rad and deg come with in si;, and math::sin(90.0<deg>) is 1. A value with any other unit, such as metres, is E0411. exp, log, log2, log10 and the exponent of pow take plain numbers the same way.
  • pow(x, n) with a unit on x needs a constant whole n, and the powers multiply: math::pow(3.0<m>, 2) is 9.0<m^2>. A n that is not a constant is E0404, as with **. With a plain x, any plain n will do.
  • The result is a number with a unit like any other: it can be stored in a float64<m>, added to other lengths, and so on.

Whole numbers

Given a whole number, sqrt, log, log2, log10 and pow use a whole-number version and give the same whole number type. The result is the true result rounded down:

  • sqrt(x) is the largest r with r * r <= x: math::sqrt(10u32) is 3.
  • log(x) is the natural logarithm, log2(x) and log10(x) the others, rounded down: math::log10(999u32) is 2 and math::log2(1000u32) is 9. They are exact for every width, uint128 included.
  • pow(x, n) is the exact whole-number power, the same as x ** n, and follows the overflow setting. A negative exponent follows ** too: it gives 0, or 1 or -1 for a base of 1 or -1.
  • floor, ceil and round of a whole number are the number itself.

A negative number to sqrt, or zero or less to a logarithm, has no whole-number result either; the call fails with math::MathError as the float versions do.

Because the rounding may not be what was meant, each of these calls gives the warning W0117, with the fix for a fractional result: convert first with value::to<float64>(). A pow with a constant exponent of zero or more has no fraction and gives no warning.
