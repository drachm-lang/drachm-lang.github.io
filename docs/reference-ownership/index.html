Moves and copies

When a value moves, how to keep it with copy, taking a field out, and the errors the compiler reports.

The ownership lesson introduces these rules with examples, and the ownership and borrowing guide explains the thinking behind them. This page states them in full.

What moves

A string, a struct that is too big or that holds a string, and a &mut borrow do not copy by themselves. Assigning, passing or returning one moves it: the new place owns the value, and the old name has none until it is given a new one. Using a name after its value moved is error E0301.

Numbers, bools and small plain structs copy by themselves, so they never need copy. A & borrow copies too, because it only points at something; see Borrowing below.

Keeping the value with copy

copy name makes a separate value and leaves name as it is. It works on a variable, a field (copy p.name) or any other expression that gives a value.

Taking one field out

Moving a field out of a struct you own must say so, and a plain string m = p.name; is error E0324 with take p.name and copy p.name as fix-its. take p.name moves the field out and leaves it with no value until it is assigned again, and the other fields stay usable. take p.title leaving "none" puts a new value back in the same statement, so the field stays usable.

A struct with a drop() method must stay whole, so a plain take out of it is E0325, while take f.path leaving "" is allowed.

Enums

An enum is one value for these rules. It is Copy when every value in every variant is and it is at most 32 bytes; otherwise it moves like a string. A match does not move the value it looks at, and take and copy in a pattern say what happens to a payload that owns memory: see Enums.

Changing things

Three words say what may change, and the compiler checks every change against them.

  • mut on a binding lets it be given a new value, and lets its fields and its contents change.
  • open on a binding (open string xs) lets its contents change: its fields, +=, and a &mut borrow. It is never given a new value. open string xs; without a value may be given its one value later.
  • mut before a field lets that field change in a struct you own, even when the binding holding the struct is not mut.

Other move errors

E0301 is also reported when a value moved in a loop is used again in the next round, when it moved on only some paths, and when p is used as a whole after p.name was taken. E0310 means a function that only borrows a value cannot move out of it, self included, so return a copy: return copy self.name;.

E0313 and E0332 say a field cannot be given a value while the struct holding it has moved (E0313) or has no value yet (E0332), so give the whole struct a value first. E0315 means a struct holding a &mut cannot be copied.

Two neighbours are checked in the same pass. E0207 means a binding declared without a value was read before every path gave it one, and E0105 means a function that promises a value can reach its end without a return. See the error index for every code.

Borrowing

A borrow lets a function use a value without owning it. &string is a shared borrow: it reads. &mut string is a unique borrow: it reads and changes. The call site says which one it passes, by writing & or &mut before the argument, and leaving it off is error E0321.

Through a borrow you use the value as if you held it: s::len() and p.hp read it, and s = ... or p.hp = ... on a &mut writes through to the original, dropping the old value first. A borrow can be returned too, as name_of does, as long as it points at something the function was given.

lend

A &mut borrow is used up when you pass it on, like any other value that does not copy. To pass it on and keep using it, write lend: grow(lend s) hands grow a temporary borrow of what s points at, and s is yours again after the call. Calling a method on a &mut binding does this by itself.

Passing the binding itself (grow(s)) moves it, and using s afterwards is E0301. lend only works on a &mut you hold; a & is shared already, so you simply pass it again.

The rules

At any moment a value has either many & borrows or one &mut borrow, never both. A borrow lasts until its last use, not until the end of the block, so this is fine:

While a borrow is going to be used again, the value it points at cannot be changed (E0302, E0303), read another way when the borrow is &mut (E0304), moved (E0305) or dropped (E0306), and a function cannot return a borrow of something it owns (E0307).

When a value dies

A value that still has an owner when its scope ends is destroyed there. For a string that frees its text. Several values dying at the same } go in the reverse of the order they were declared in, so the last one made goes first. A value that was moved away is not destroyed by its old name, because the new owner does that: only what still holds a value when the scope ends is dropped, and a struct with some fields taken out drops the ones that remain.

A temporary, such as the "a" + "b" in ("a" + "b")::upper(), dies at the end of the statement that made it. In the condition of a while that means every time round; in the condition of an if it means before either branch runs.

Failures and drops

A failing function that ends with fail (or a fails that passes a failure up) drops what is alive exactly as a return does: its locals, and the temporaries of the statement it was in. The failure value itself moves up to the caller, or is dropped when the caller gives a maybe fallback.

drop()

A struct can name what happens when it dies by giving it a method called drop that returns none. It runs when a value of that struct is destroyed, before the struct's fields are dropped, and the fields then go in the order they were declared. You cannot call drop yourself: x::drop() is error E0331.

destroy

destroy x; runs drop() now instead of at the end of the scope, and ends x like a move does: reading it afterwards is error E0301, and nothing runs for it at the end of the scope. It works on a variable whose struct has a drop(); anything else is E0901 for now.

If destroy is on only some paths, the compiler remembers at run time whether the value is still there, so the scope end drops it on the paths that did not destroy it and only on those.

Lambda captures

A lambda borrows the enclosing bindings it reads and infers a mutable borrow for a binding it changes. A move lambda owns the values it captures. See Captures for examples and borrow duration.
