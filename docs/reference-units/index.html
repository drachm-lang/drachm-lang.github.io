Units of measure

Declaring units, the SI set, numbers with units, arithmetic and conversion, points and deltas.

A number can carry a unit: float64<m> is a number of metres. The compiler checks that you never add metres to seconds, and then forgets the units: a program with units runs exactly as fast as the same program with plain numbers.

Units that you write in one file are visible everywhere in it, in any order. in si; adds the common SI units (see The SI set).

Declaring units

unit only starts a declaration at the start of a top-level item, so it is still a fine name for a variable or a function. Unit names are plain ASCII letters, digits and _, and live in their own namespace: a variable s and a unit s do not clash. Two units that mean the same thing are the same type: float64<N> and float64<kg*m/s^2> can be used for each other.

A unit can be declared without a base unit, as a plain ratio: pct above is a number with a name. 85<pct> stripped to a plain number is 0.85.

The SI set

in si; brings in the SI units, so you do not declare them yourself:

It has the base units m, s, kg, A, K, mol and cd, rad for angles (and deg, which is 0.017453292519943295 rad, so math::sin(90.0<deg>) is 1; see Maths), and the derived ones: N, Pa, J, W, C, V, F, ohm, S, Wb, tesla, H and Hz. Scaled units are declared the same way: g (0.001 kg), mm, cm, km, mg, ms, us, ns, min (60 s), h (3600 s), kHz, MHz, GHz, kJ, kW and kN, plus the point degC.

Prefixes are not automatic: km is a declared unit, not k applied to m. You can declare your own scales the same way: unit mi = 5280 ft;. A file that declares a name in si; already has is an error (E0403).

X as unit names the unit X out in full, anywhere a unit can be written: float64<tesla as unit> is the same type as float64<tesla>, and 0.5<tesla as unit> is the same value as 0.5<tesla>. It is also how a unit is reached where a type parameter has the same name. A type parameter named like a unit is allowed with a warning (W0618). Inside its scope the plain name is the type, so float64<K> there is an error (E0402); float64<K as unit> is the unit K.

The SI name K is kelvin. In a program that has in si; and a type parameter K, write float64<K as unit> for the unit wherever a plain K would be the type.

Without in si;, a unit such as m is unknown and the compiler says so (E0402). in si; is per file, like every import: a file that uses SI units imports si itself, even when another file of the project already does.

Numbers with units

Write the unit after a number type, float64<m/s>, uint8<km>, or directly after a number literal, 9.6<s>, 100<m>, 2.5f32<m/s>. There is no space between the number and <: 9.6 < s is a comparison. A literal with a unit gets its number type like any other literal, from the place it is used.

Whole numbers can hold units too. They cannot hold fractions of a unit, so uint8<km> s = n; with n equal to 300 m gives 0 (and warns, see below).

A plain number beside a measure in +, -, % or a comparison needs a unit (E0408): write d + 5<m>. This holds for a variable as well as a constant. The one exception is zero, which has no unit: d + 0 and speed > 0 are fine. A point is different: 0 is a real temperature, so write 0<degC>.

Number types work as they always do: the left side leads, so 2.5 * dist is a float64<m>, and a uint32 times a float64<m> gives a uint32<m>.

When every unit cancels, the result is a plain number with the scale folded in: 4.0<km> / 2.0<m> is 2000.0, and pct * pct is a plain number too.

Scaled units

Scaled units of one kind convert to the unit of the left side: 10<km> + 100<m> is 10.1<km>, and 10<m> + 1<km> is 1010<m>. For two values with different scales both sides are brought to a common base, added, and brought back, so 2<mi> + 2<mi> with unit mi = 5280 ft; is (5280*2 + 5280*2) ft / 5280. When both sides have the same unit nothing is scaled at all.

Whole numbers truncate toward zero when a unit shrinks, and the compiler warns (W0102) that the conversion can lose information, or that a unit that grows can overflow. Say it is intended with x::in<km>(). A value that does not fit wraps around, as ::to<T>() does. The scaling follows the overflow setting like any other arithmetic: under saturate a value that does not fit stops at the end of its type, and under panic it stops the program (see Overflow).

::in and ::to

x::in<km>() changes the unit and keeps the number type. x::to<float32>() changes the number type and keeps the unit. A unit inside ::to<...> is E0407, and so is ::in to a unit of another kind.

Measures and plain numbers

A measure can go into a plain number slot. It becomes the amount in the base unit: uint32 t = 3<km> is 3000, and float64 f = 5.0<g> is 0.005 when g is 0.001 kg. Whole numbers warn when this truncates.

The other direction works where a unit is declared: a plain value gets that unit. float64<m> d = 5; is 5 m, and d = 0; is 0 m. Passing a plain number to a parameter with a unit, or returning one from a function with a unit, works the same way. d++ adds one metre. Only operators are strict: d + 5 needs its unit, as above.

Printing

::text() prints the number only, and ::unitText() gives the unit as a string. You lay the two out:

::to<string>() is an error: use ::text() to make a string from a number.

Points and deltas

A unit declared with offset is a point on a scale, like degC. The difference of two points is a delta, written delta degC.

  • point - point is a delta; point + delta and point - delta are points.
  • point + point, a point times anything, and -point are E0409.
  • delta degC has the size of a kelvin: it converts freely to and from K, and ::unitText() of a delta prints delta degC.
  • Points compare with points. A bare 0 is not unit-free beside a point (0 degC is a real temperature): write 0<degC>.
  • A point converts between units with its offset, and into a plain number it gives the reading in the base unit: 20.0<degC> is 293.15.

Generic over units

A function, struct or enum can take a unit parameter (unit U) and work with any unit; the unit of each use is worked out from the arguments, or written with unit in the type arguments (Track<float64, unit m>). See Generic over units.
